# 创新立意与同类平台比较

## 项目围绕什么问题立意？

建议立意为：**把已有衣物转化为可解释的个人决策资源，让日常穿搭更容易，也让被遗忘的衣物有机会重新进入选择。**

| 问题 | 项目设计回应 | 可以验证的指标 |
|---|---|---|
| 衣物照片分散、属性不清楚 | 快速入柜、图片整理、属性证据状态和人工修正 | 录入耗时、基础图成功率、属性修正率 |
| 只给一套结果，用户不知为什么 | 规则命中记录、维度评分、入选与未入选解释 | 理由与衣物一致率、用户理解程度 |
| “甜一点”“多巴胺”等表达过于粗糙 | 18 个风格画像，按具体线索计算 | 标注风格检索命中、反例误判 |
| 推荐长期集中在少数衣物 | 动态召回、曝光债、跨天轮换与主体多样化 | 衣物曝光覆盖、单品最高占比、重复首页 |
| AI 任务等待、断网或失败后状态不清楚 | 持久任务、资源许可、生成快照、UNKNOWN 边界 | 重启后状态一致性、重复派发次数 |
| 用户反馈被忽略或永久固化 | 多层反馈、时间衰减、可恢复冷却和可清空画像 | 反馈即时生效、恢复后的行为变化 |

可持续利用是立意；“减少消费多少”“降低碳排多少”需要另做对照研究，现有代码和模拟实验不足以支持这些数字。

## 鱼搭有哪些可以展示和证明的差异？

下表是对鱼搭自身实现的分析；竞品公开材料不足以完成相同维度的内部比较。因此使用“我们的实现特点”，不使用“其他平台都做不到”。

| 实现特点 | 项目证据 | 用户价值与竞赛表达 |
|---|---|---|
| 推荐决策与语言模型分工 | `RecommendationEngine`、`OutfitScorer`；页面推荐与微调走业务接口 | 可重复计算、可以解释；外部模型调用有明确用途 |
| 可解释的中文风格线索 | `style-looks.json`、`StyleLooks`、风格反例测试 | “千金风”不会只被理解成甜美/正式标签；能说明具体颜色、面料和细节 |
| 两条候选生成路径 | 普通召回组合与已审核搭法填位，共用规则和评分 | 避免只在一个截断候选池中选；把搭法知识转成可执行约束 |
| 曝光均衡进入算法 | `Balance`、动态 K、曝光债、跨天限流 | 兼顾匹配质量与衣柜覆盖，减少总推同几件 |
| 反馈有粒度与恢复机制 | 整套、单品对、类别对、单品、规则倾向及衰减 | 区分“不喜欢这件”和“不喜欢这样配”，允许改变主意 |
| 助手操作按真实结果确认 | 后端授权、SSE 命令、浏览器 ACK、revision 验证 | 能查看执行状态、停止并接手，减少口头完成与实际状态不一致 |
| 本地能力与可控部署 | 本地 ONNX；本地/S3 存储；默认关闭的管理模块 | 适合可控环境演示与部署；外部服务失效时保留基础能力 |
| 生成过程有费用和数据边界 | 准备→确认→任务；冻结输入；幂等键与 UNKNOWN | 用户知道提交什么；未知上游结果不盲目重复派发 |

对应的源码入口与设计参见 [核心算法](04-核心算法与实现依据.md) 和 [核心设计](05-核心功能与系统设计.md)。

## 应当怎样界定“创新”？

**应用立意**：围绕真实个人衣柜的日常决策和衣物利用，建立录入、检索、选择、编辑、预览与反馈闭环。这个方向有同类产品，贡献在具体落地与验证。

**算法设计与组合**：把领域知识变成可版本化的规则与风格线索；将普通组合、审核搭法、个性反馈及曝光均衡放入统一的评分流程。可以作为项目的技术设计贡献，不应声称证明了全球首创。

**人机协作设计**：自然语言负责表达意图，代码负责可计算决策，后端负责授权，浏览器负责实际执行并回执。用户能解释、编辑、恢复和接手。

**工程设计**：共享资源许可、账户公平调度、持久化执行记录、生成输入快照和保守恢复，针对真实 AI 产品的限流、耗时、重复计费风险形成完整机制。

U²-Net、BGE、Chinese-CLIP、ONNX、LangGraph、k-means、余弦相似度、DCT 感知哈希均来自已有技术。项目没有证据证明自行训练了基础模型、提出了新的神经网络结构或使用了强化学习。

## 竞争优势需要补什么证据？

当前可以用源码、守护测试和历史仿真实验支持实现特点。要进一步声称“更快、更好用、更符合审美”，需要在相同衣柜、相同任务和一致评价协议下比较。优先开展：录入耗时、搭配选择耗时、推荐采纳与理由可信度、四周实际穿着覆盖、外部调用费用。

鱼搭也有明确不足：当前未证明达到竞品的社交、购物导入、日历规划和成熟用户生态；生成图存在细节漂移；属性质量影响推荐；本地模型占用内存。承认这些边界，可以让优势更可信。
