# 鱼搭：让已有衣物成为可理解、可组合的个人衣柜

## 衣柜已经装满，为什么仍然不知道穿什么？

出门前，用户面对的往往不是一件衣服，而是一连串选择：今天的场合和温度适合什么？这件上衣能配哪条裤子？那件很久没穿的裙子还能怎么搭？即使收藏了很多穿搭照片，也未必能用自己已有的衣物还原。

鱼搭从这段日常决策出发，建立一个面向已有衣物的数字衣柜。用户拍照录入衣物，系统整理图片与属性，按照场景、天气、风格和个人反馈生成搭配，并把选择依据交给用户查看。用户可以换一件、换一批、进入搭台编辑，也可以在确认后生成个人 OOTD 效果预览。

项目希望帮助用户理解和使用自己的衣柜，减少重复选择与闲置。提高实际穿着率、减少不必要购买是产品目标，仍需要长期用户研究验证。

## 从一张照片到一次穿搭，系统做了什么？

设想一名用户准备第二天通勤，想穿得精致一些，但不希望总是出现同一双鞋。

她先把衣物照片录入鱼搭。系统保存原始资产，通过本地抠图形成透明衣物素材；复杂背景、主目标不明确或抠图不理想时，可以定位目标、保留基础图并进行后续处理。识别结果区分已确认、推测、未知与冲突，用户可以修正属性，系统不会把模型猜测直接当成可靠事实。

接着，她选择通勤场景，或向助手表达“明天通勤，想要千金风，换双鞋”。推荐引擎从她自己的衣物中召回候选，检查穿着结构，计算配色、冷暖、场景、风格与个人偏好等得分。对“千金”“多巴胺”等风格词，系统按颜色、面料、图案和细节线索计算吻合度，而不是只检查一个粗风格标签。

推荐卡片给出具体衣物、亮点与依据。用户既能看到“为什么这样搭”，也能查看“为什么没推荐那件”。如果只是想换双鞋，系统重新计算替代品；如果反馈某个组合不喜欢，后续推荐会调整，用户也可以恢复或清空相关偏好。

用户把满意的方案放入搭台，在多画板中调整布局、图层和素材。助手执行画板操作时，后端发出命令，浏览器完成实际操作后回执确认；聊天中的一句“已完成”不能代替真实执行结果。

最后，用户选定已确认的基准模特和已保存搭配，核对生成参数、参考图片与额度，再提交 OOTD。可以选择预设动作或自己的动作卡，结果也支持单独调节身材比例并生成新图。生成图用于观察视觉效果，仍需人工核对衣物细节，不能证明真实合身。

## 为什么把推荐交给代码，把对话交给模型？

大量穿搭判断可以计算：有哪些衣物、是否缺少主体、颜色是否呼应、保暖是否合适、最近是否总推同几件。鱼搭把这些步骤放到可重复的算法中，保留每项评分与规则依据。

大模型用于理解自然语言、图片识别和生成视觉内容。助手拿到经过筛选的紧凑结果，帮助用户理解与操作。页面推荐和推荐微调可以直接运行计算流程，不需要每次把整个衣柜发给远程模型。

这种分工同时服务于三个目标：控制外部调用、让推荐有依据、让权限与执行结果掌握在业务后端。具体创新及竞品比较见 [创新立意与竞品对比](02-创新立意与竞品对比.md)。

## 项目的技术和工程完成度体现在哪里？

用户端采用 Vue 3、TypeScript、Ant Design Vue 和 Konva；业务后端采用 Java 21、Spring Boot、H2、Flyway 与 MyBatis Plus；助手使用独立的 TypeScript/LangGraph 运行时。本地图像与语义推理通过 ONNX Runtime，图片也支持本地存储或 S3 兼容对象存储。

系统已经建立衣物、搭配、画像、任务、图片资产和生成结果的持久化链路。耗时操作进入统一任务执行器，区分 CPU、识别和生成资源，处理额度、并发、限流与重启恢复。对已经发给上游而结果不确定的请求保留 UNKNOWN 状态，不自动重发。

项目还提供默认关闭的可插拔管理接口，用于账号、模板审核、运维与去标识统计。用户衣柜与私有图片受账号归属控制，敏感记忆按用途授权。相关实现与边界见 [核心功能与系统设计](05-核心功能与系统设计.md)。

## 如何用一段话介绍？

鱼搭是面向已有衣物的可解释 AI 数字衣柜与穿搭决策系统。项目打通照片入柜、混合检索、算法推荐、多画板编辑、个人 OOTD 预览与反馈调整。推荐引擎把结构约束、审美规则、风格线索和曝光均衡结合起来，给出具体依据；大模型负责自然语言、识图与生图。通过本地推理、明确的生成确认和持久任务管理，鱼搭探索一种可解释、可控制、可持续使用的个人穿搭工具。
