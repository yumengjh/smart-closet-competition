# 鱼搭竞赛材料

本仓库专门存放鱼搭参赛资料（原位于 smart-closet-server/competition，未入库）。相对链接按 `smart-closet-server`、`smart-closet` 与本仓库同在 `~/project/` 下编写。

首轮整理：2026-10-13；增量更新：2026-10-18（见 [08 增量更新](08-增量更新-2026-10-18.md)）。参赛团队：鱼力无限。项目定位：**面向已有衣物的可解释 AI 数字衣柜与穿搭决策系统**。

建议主线：把真实衣物变成可计算的个人衣柜，让用户知道有什么、找到怎么搭、看见为什么、按自己的反馈调整，再通过搭台和 OOTD 预览完成决策。

## 哪些表述可以直接使用？

- 推荐主引擎由代码完成候选召回、组合、评分和多样化；页面推荐、换一批、换一件不依赖远程大模型决策。
- 检索可使用本地 ONNX 向量推理；“零远程模型调用”不表示完全没有模型推理，也不表示服务器没有运行成本。
- 聊天、图片识别、图片增强、个人 OOTD 等能力仍依赖配置的上游服务。
- U²-Net、BGE、Chinese-CLIP 为复用的预训练模型；项目贡献主要在算法组合、领域规则、反馈机制、交互执行和工程闭环。
- 历史实验有明确的样本、环境与日期，不能当作当前线上规模、用户穿着率或节省费用的实测。

本轮完成源码与文档扫描、公开竞品核查和文档校验，未启动服务、调用收费模型或重跑业务测试。比赛名称、赛道和页数要求尚未给出，材料采用通用版本；后续可以据具体模板裁剪。

## 建议如何组织申报书和 PPT？

申报书按“问题与目标 → 同类产品与差异 → 核心设计 → 算法 → 技术栈与选型 → 验证与局限”组织。PPT 优先讲一名用户完成一次穿搭的故事，再用两三页解释算法与实验，技术栈放在架构页；依赖清单放附录。

整理过程和可追溯信息在 [整理记录](整理记录/progress.md) 中。
