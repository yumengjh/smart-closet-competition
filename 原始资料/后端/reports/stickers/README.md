# 贴纸化 · bold-v2

日期：2026-09-27。查看 [12 张完整预览](index.html)。每组依次为原抠图、贴纸在浅色背景上、同一贴纸在深色背景上。

## 已实现

- 将已有干净抠图作为输入，等比例居中到 1024×1024 透明画布，衣物最长边 848 像素。
- 描边从 8 加粗到 32 像素；阴影不透明度从 18% 提高到 32%，偏移从向下 10 改为向右 8、向下 18 像素，模糊 sigma 从 6 改为 10。
- 外部背景按与画布边缘的连通关系识别，封闭的透明孔洞不填白、不添加投影。
- 原始抠图文件、蒙版与分割元信息保持原样。缩放展示图会重采样像素，半透明通道允许 8 位预乘 alpha 带来的取整差。
- 独立生成、独立缓存，无需重新运行分割模型。没有新增依赖或安装软件。

## 接口

```text
POST /api/segmentations/{id}/sticker        首次 201；已有结果 200
GET  /api/segmentations/{id}/sticker        元信息；尚未生成 404
GET  /api/segmentations/{id}/sticker/image  透明 PNG；尚未生成 404
```

POST 无请求体，当前使用固定样式。响应包含 `style: bold-v2`、`imageUrl`、1024×1024 尺寸、衣物在画布中的 `contentBounds`、首次生成时间与耗时。同版本复用落盘缓存，重启后依然可读；同时只处理一个贴纸渲染任务，忙时返回 429。

可调常量集中在 [StickerRenderer.java](../../src/main/java/com/smartcloset/image/StickerRenderer.java) 顶部：画布、留白、描边宽度/颜色、阴影颜色/不透明度/偏移/模糊。修改时升级 `STYLE`，重新构建/启动后再调用 POST；落盘目录和图片缓存标识随版本变化。

上一版两张透明贴纸保留用于比较：[紫色旧版](previous-soft-v1/artf-280.png)、[蓝色旧版](previous-soft-v1/artf-248.png)。

原分割 ID 不存在时返回 404。框选重做会产生新 ID，其贴纸也独立生成。预览中的 ID 来自历史比较结果，在其他存储目录运行服务时应使用实际上传返回的 ID。

## 目视检查

已查看全部 12 组浅色、深色背景对照：

- 统一画布后，衣物在卡片中的尺寸更一致；加粗后的暖白轮廓在浅/深背景上都有明显的纸边厚度，右下方投影更清楚。
- 200、208、216、228、240、260、280、320 的主体、印花和原始褶皱保留，未为了展示自动转正或重画。
- 100、140 袖口的软边与阴影仍跟随原抠图；120 右袖阴影边缘发虚，248 蓝色衣服的袖口缺陷在深色背景上尤其明显。
- 贴纸化可以改善呈现，但不会把错误蒙版修好。248 应交给用户重新拍摄或后续局部修正步骤。
- 下载 PNG 仍为透明背景；浅色/深色底仅存在于预览，不写入贴纸。
