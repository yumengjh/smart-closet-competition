# 相似衣物提示与以图搜图报告（2026-10-09）

设计：[相似衣物提示与以图搜图设计](../../docs/design/2026-10-09-相似衣物提示与以图搜图设计.md)（S1~S8）。分支：前后端均为 `feat/similar-garments`（后端基于 `feat/management-ops-kpi`，前端基于 `feat/outfit-fullbody`），**未合并到 main**。

## 一、做了什么

| 部分 | 内容 |
|---|---|
| 图像指纹 | 纯 Java：64 位感知哈希（DCT）、8×8 轮廓网格、外框长宽比、色板；透明图按透明度、普通图按背景色差找衣物；绑定展示图版本，后台 `VISUAL_INDEX` 每 30 秒补算，草稿也算 |
| 相似度 | 描述向量、实测颜色（两边色板互比）、轮廓、外观、识图字段五项白盒加权，缺数据的项不参与；必须是同一穿着位置；品类大类不同封顶 0.6；识图字段里品类或图案不同不算重复 |
| 等级与理由 | 可能重复 / 非常像 / 相似，每条带“颜色几乎一样（ΔE 2）”“轮廓很接近”等理由 |
| 衣物详情 | “相似的衣物”最多 5 件；有可能重复时顶部提示，可点“不是重复” |
| 未入柜 | 疑似重复的草稿卡片下标“可能重复：某某” |
| 我的 → 整理衣柜 | 成对列出可能重复的衣物，可标“不是重复” |
| 以图搜图 | “我的衣柜”右上角入口；可选位置；本地抠图后比颜色、轮廓、外观；界面写明认不出“同款不同拍法” |
| 接口 | `GET /api/garments/{id}/similar`、`GET /api/garments/duplicates`、`GET /api/garments/similar-flags`、`POST /api/garments/similar-dismissals`、`POST /api/garments/search-by-image` |

全部零模型调用、零新增模型文件、图片不外传。

## 三、真实运行自测

自测库放入 6 件带图片的衣物：两件同图的海军蓝 T 恤、红色 T 恤、白色宽条纹的海军蓝 T 恤、牛仔裤、一件颜色稍有不同的海军蓝 T 恤草稿。启动服务后后台自动补算指纹。

| 检查 | 结果 |
|---|---|
| 可能重复列表 | 第一版把“条纹 T 恤”和“纯色 T 恤”也判成重复 → 修正后只剩真正同图的一对 |
| 未入柜草稿 | 标出“可能重复：海军蓝T恤（又录了一次）” |
| 以图搜图（米色背景的普通照片） | 第一版条纹 T 恤 0.75 排第一（抠图留了背景）→ 修正后两件纯色 0.83 在前、条纹 0.69 在后 |
| 耗时 | 首次约 3 秒（本地抠图库冷启动），之后约 0.7 秒 |

截图（详情相似面板、未入柜标记、整理衣柜、以图搜图、手机端）已在会话中提供，按约定不入库。

## 四、能力边界（如实）

- 能可靠发现：同一张或几乎相同的图（重复录入、连拍、截图）、颜色和轮廓都很接近的衣物。
- **认不出**：同一件衣服换了角度、光线，或者平铺对上身。这需要第三期的本地图像向量模型。
- 门槛是按经验和合成图设定的初始值，需要用真实衣柜数据和“不是重复”反馈再校准。
