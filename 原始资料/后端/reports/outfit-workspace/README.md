# 多画板与 Agent 临时搭台验收

日期：2026-10-02。隔离账号、独立数据库，8081 / 8092 / 8765，真实浏览器操作。模型使用本机模拟上游，未调用收费模型；图片为带背景流程样例，不能证明真实搭配的审美效果。

## 已实际检查

- 三套搭建：18 个实际执行步骤，逐步回执后继续，三个独立画板；后续指定五套，追加五块到原会话（共八块），没有替换旧画板。
- 修改与撤销：当前临时画板向右移动 30px，撤销与重做恢复坐标；其他画板保持不变。验收修复了同步回写造成版本误增、撤销栈丢失的问题。
- 普通搭配：打开已保存搭配后要求修改，复制到当前会话临时画板，原画板 x=540，副本 x=570，保留原搭配 ID 与版本供明确覆盖。
- 对齐：通过 Ant Design 分组将一张样例设为 BOTTOM，再整理穿搭；TOP / BOTTOM 中心均为 x=540，接缝约重叠 19px，等比缩放误差仅像素取整。整理可撤销与重做。样例不是实际裤子，真实素材的观感仍需体验。
- 批量保存：勾选两块、确认保存；两套分别获得 outfitId / revision 与已保存标记，第三块继续作为草稿。
- 停止与面板关闭：关闭聊天仍看到正在添加衣物的步骤和极光；停止后九块画板保留，最后一块已有两张贴纸，所有锁解除，没有继续追加后续画板。
- 容量：已有十块时要求新增五套，仍为十块，所有画板解锁，容量不足拒绝开工。
- 保存冲突：另一次更新原记录到 revision=1，临时副本仍持有 sourceRevision=0；确认覆盖被拒绝，保留草稿与错误提示。取消覆盖后另存新搭配成功，不再显示冲突。
- 刷新：十块画板及保存标记恢复，锁数为零；不会自动恢复执行。
- 减少动态效果：真实执行中观察 prefers-reduced-motion=true，极光 computed animationName=none；实际微调成功。
- 桌面 1440×1000、手机 390×844 与 320×640：页面没有横向溢出；窄屏工具栏单行，底部四个操作按钮避开悬浮球，「更多」菜单可正常打开。320px 屏幕画板视口约 202px 高。
- 接口流：首帧约 49ms；修复 Spring 响应缓冲，命令可在等待回执前到达浏览器。后端校验顺序、版本、所属账号、衣物集合、贴图身份和无关贴纸保留。

## 构建与边界

前端 npm run build:server（含 vue-tsc）发布到后端 static；Node npm run build；Java mvn -q -DskipTests package。未新增或运行测试套件。Vite 仍有现有组件库大 chunk 提示。

未验证真实模型的搭配质量；没有本轮付费上游调用。批量部分失败重试、跨设备缺少本机草稿、存储额度不足、真实人物混合素材和所有裁剪／导出手势未全部逐项浏览器验收。实现保留旧接口和编辑器机制，需要后续使用中关注这些边界。
