| 检查 | 结果 |
|---|---|
| AWS 官方文档 SigV4 示例：GET 带 Range、ListObjects、预签名 GET（`SigV4Test`） | 3 个签名逐字节一致 |

## 自动化测试（CI 每次都跑）

- `FakeS3`：测试用 S3 端点，按实际收到的方法、原始路径、原始查询串和已签名请求头重新计算签名，不符时返回 403。
- `S3BlobStoreTest`：读写、HEAD、分页列举、删除；503 自动重试；密钥错误时给出可读原因；预签名链接能下载，篡改后返回 403，同一时间窗内链接不变；配置校验，且 `toString` 不含密钥。
- `S3StorageIntegrationTest`：整个应用跑在存储桶上：
  - 衣物图写入桶，本机不落文件，读取时校验 sha256。
  - 普通请求返回 302 到直链；带 `Origin` 的画布请求由后端转发字节。
  - 私人图片返回 `no-store`，只有本人能拿到直链；删除后对象消失，删除记录留在本机。
- `StorageMigrationTest`：
  - 只迁移图片类文件。数据库、锁、临时文件、删除记录和备份都不动。
  - 对象键与本机相对路径一致；重复执行只发 HEAD，不重复上传。
  - `verify` 能发现桶里缺失的对象和改动过的文件。
  - `pull` 能把桶里的对象拉回空目录。
  - 区分「迁移漏掉」和「本机原本就缺失」。
- `S3CompatibilityTest`：设置 `CLOSET_TEST_S3_*` 后会对真实的桶（如测试用 COS 桶）跑一遍完整读写，并清理写入的对象；没设置时跳过。

## 迁移脚本端到端（本机目录模式 + moto S3）

- **数据准备**：用打包后的 jar 先建一个带完整数据库结构的存储目录，再放入衣物图、凭据和私人照片。
- **执行顺序**：`scan` → `copy`（上传 3 个）→ 再 `copy`（3 个全部跳过）→ `verify` 通过 → `pull` 到空目录，拉回的文件与原文件逐字节一致。
- **发现并修复的问题**：主机没有 UTF-8 locale 时（容器里常见），中文输出变成 `???`。迁移命令现在固定用 UTF-8 输出；在 `LANG=C` 下复测正常。

## 全量测试

`mvn -o test`：563 个，失败 0，跳过 11（需要外部模型或 key）。

## 未在本环境验证

- 真实腾讯云 COS：这里没有 COS 账号。迁移脚本第一步 `scan` 会调用 `probe`，桶名、地域或密钥不对会立即报错。上线前可以先跑一次 `S3CompatibilityTest`，用一个测试桶核对。
- `migrate-to-s3.sh` / `remote-storage.sh`：这里没有 Docker 守护进程，只做了 `bash -n` 和 shellcheck 检查。服务器上实际执行时，每一步出错都会停下；停服之后的步骤失败会自动切回本机存储并重启后端。
