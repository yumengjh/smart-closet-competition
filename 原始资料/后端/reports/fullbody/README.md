## 一、做了什么

| 部分 | 内容 |
|---|---|
| 分类修正（D43） | 新位置：背带裙/背带裤/JSK（`OVERALL`，需内搭）、头饰（`HEADWEAR`）、手持物（`HANDHELD`）；袜子扩展为袜子/裤袜。按固定顺序匹配：**裤袜/连裤袜不再被当成下装**；小黑裙、礼服裙、OP、水手服/西装套装归连衣；SK 归下装；伞裙、娃娃领衬衫、娃娃鞋、手拿包、袜靴不误判。前端搭台同步，背带裙压在上衣之上并与之重叠 |
| 一体裙+内搭（D44） | 主体组合新增“上装+背带裙/JSK”；一体裙在配色与鞋款兼容中按下装处理；今日灵感遇到只有一体裙的模板会自动补一件上装 |
| 配件建议（D45） | 每套最多 3 条（袜子/裤袜、头饰、帽子、包、手持物、围巾），**不改总分**。穿裙子 <15°C 优先建议裤袜并说明原因，≥22°C 不建议；衣柜没有裤袜时提示；头饰与手持物只在风格对得上或被点到（“带上小熊”）时出现；围巾 <12°C；毛线帽只在冷天。卡片显示“可以搭配：……”，详情列理由；助手卡片也带配件名 |
| 风格模板（D46） | 资源文件 draft-4：新增 8 条草稿（洛丽塔 JSK 两条、背带裙、背带裤、JK 百褶、冬季裙装+裤袜+靴、小黑裙、水手服），全部待审核 |

| 文档 | 设计文档、采集规范、帮助文章（新单品、配件建议、整套穿搭样本）、总设计状态行与后续池、AGENTS.md 约定、文档索引、本报告 |

## 三、端到端自测（假识图服务）

这个环境没有识图密钥，也连不上外部图片站，所以没法“搜一两张图试真实效果”。改为在本机起一个 OpenAI 兼容的假服务，返回一份固定的洛丽塔穿搭提取结果，后端走**真实的提取代码路径**：

- 上传两张合成的示意图：都提取成功；同一张再传一次在调用模型前被拒（409）。
- 假服务记录到的请求：系统提示为 ootd-v1、结构化输出 `ootd_sample` 严格模式、顶层 13 个字段、输出上限 16384、图片已缩放后发送。
- 通过一条后原图文件被删除，统计显示“衬衫 + JSK”“白 + 藏蓝”，生成的模板草稿槽位为 头饰/上装/背带裙/袜子/鞋，并出现在模板审核列表的“待审核”里。
- 管理页截图（桌面与手机：样本列表、审核抽屉、统计）已在会话中提供；按仓库约定 PNG 不入库。自测时发现并修正：标签页组件未全局注册（改用已有的分段控件）、统计里的状态显示成英文。

**真实模型的提取质量没有验证过**，需要你配置好识图服务后试 1~2 张（见第五节）。

## 四、与设计的差异

| 设计 | 实际 | 原因 |
|---|---|---|
| 支持 WebP | 只收 JPEG/PNG | 沿用现有图片解码（与入柜一致），长边缩到 1600 后存储与发送 |
| 姿势进提示卡片与生图（第 3 期） | 只采集 | 按分期；开工前需确认上游生图能否控制姿势 |
| 统计进管理接口 | 只在管理页 | 与 P4 一致，管理接口另行设计 |

## 五、需要你做的

1. **试效果**：确认识图服务已配置（`.local/generation.yml`），用管理员账号打开“我的 → 整套穿搭样本”，按采集规范传 1~2 张真实整套穿搭图，看物品有没有漏（头饰、袜子、手里的东西）、位置对不对、颜色准不准。觉得可以再批量收（建议先 300~500 套）。
2. **审核模板**：资源文件里新增的 8 条风格草稿，以及样本生成的草稿，都在 `/admin/templates` 待审核。
3. **合并**：本分支基于 P4（含 P3），未合并到 main，确认后合并。
