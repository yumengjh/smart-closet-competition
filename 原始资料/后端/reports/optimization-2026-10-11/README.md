# 2026-10-11 全项目优化记录

范围：后端 yumengjh/smart-closet-server、前端 yumengjh/smart-closet。重点是搭配推荐引擎，其次是推荐服务层和前端推荐与画板页面。

## 流程

1. **外部审核**：用 gpt-6-sol 做三轮代码审核（推荐引擎、推荐服务层、前端推荐与画板）。原始意见见同目录的 `engine-review.md`、`service-review.md`、`fe-review.md`。
2. **核实**：每条意见都对照代码确认。能做成测试的，先写测试，并确认修复前失败、修复后通过。
3. **提交与合并**：每个优化点（或一组紧密相关的点）先开 issue，再开 PR，本地全量测试和 CI 都通过后合并。
4. **约束**：推荐引擎的新规则受 Mechanisms 开关控制，开关全关时仍是 P4 行为；规则参数放在 `aesthetic-rules.json`。

## 评估后暂不做（理由）

| 意见 | 结论 |
|---|---|
| 低温露腿另行扣分 | 冷暖维度已经按保暖值区间扣分。10-10 用户反馈认可「背带裙配丝袜」，裤袜作为建议出现。另加一条扣分会让低温裙装整体下沉，误伤多于收益。先观察 #31 修好的裤袜提醒效果 |
| 有鞋时无鞋方案仍参与竞争 | 无鞋方案已扣 `noShoes` 分，而且只在「衣柜里合适的鞋不多」时出现；直接去掉会误伤「只有不合适的鞋」的回退路径 |
| 搭法候选上限偏向模板顺序 | `maxFills=400`，当前模板数量远达不到上限。等审核通过的模板明显增多后再按场合分配名额 |
| 鞋位召回预留名额 | 10-10 已用同页换鞋（`otherShoe`）解决同一双鞋占满首屏，暂不再改召回 |
| 风格画像按账号缓存、曝光统计聚合 | 是性能优化，当前用户量下单次推荐耗时主要在打分，不在查询。上量后再做，并需要可重建的聚合表 |
| `present` 前校验衣柜新鲜度、`rerun` 复用天气快照 | 牵涉「回看历史」与「按当前状态重推」两种语义，需要产品决定 |
| 前端：大衣柜一次加载全部衣物、移动端重复挂载素材组件、画板键盘操作 | 需要服务端搜索加虚拟列表，或较大的组件改造。已记在 front #15，单独排期 |
