## 三、本地自测（演示衣柜，8080，模板全部临时通过审核）

- 今日灵感：66 个已审核模板中当天（秋季、日常、未设性别）适用 59 个，给出 3 套 88 分组合（"牛仔+白色，永不出错""毛衣打底+长裤，简洁保暖""毛衣+牛仔裤+靴子，秋冬经典"），每套首条亮点为来源搭法；"差一件"给出 3 条（含 1 条流行模板）。
- 截图自测发现并修正：模板"纯色上衣配花纹下装"的下装槽位只限制了花纹上限，素色牛仔裤也能命中 → 槽位新增 `patternMin`，修正后该模板转为"差带花纹的下装就能穿……"提示；"高领打底+长裤"无法核对领型 → 改为"毛衣打底+长裤"。均已加测试。
- 统计卡片：近 30 天 33 套（助手 24、推荐区 6、今日灵感 3），本地计算 9 套；该演示库的助手调用发生在 `model_usage` 上线前，所以 token 为 0。
- 天气：本容器无法访问 Open-Meteo，走降级路径，卡片标"未提供温度，按日期推断为秋季"，与设计一致；正常路径由 `OpenMeteoWeatherTest` 的本地桩覆盖。

## 五、与设计的差异

| 设计原文 | 实际 | 原因 |
|---|---|---|
| 5.13 用 OpenCV k-means，k=3~4 | 纯 Java，k=3 | 不新增原生依赖；展示图已抠图，3 类足以区分主色、辅色和阴影 |
| 第七节 `V17__garment_color.sql` | `V20__recommend_p4.sql`（含取色、`model_usage`、`template_id`） | V17~V19 已被 P2/P3 使用 |
| 5.18 管理接口与设置页均可看统计 | 只在设置页 | 管理接口按可插拔原则另行设计，列入后续池 |
| 5.18 按功能（推荐、搜索、闲聊、生图、识图）汇总 | 推荐类全部零模型，只统计助手 token 与两类额度 | 搜索和推荐不消耗模型，单列没有意义 |
| P5 多模态复核 | 未做，移入后续池 | 用户要求收官；需要付费视觉调用 |

## 六、需要你决定或操作的事项

1. **审核模板**：66 条模板（含 8 条流行草稿）都是"待审核"，今日灵感在审核通过前只会显示提示。到 `/admin/templates` 按"流行/经典"筛选后逐条或批量通过。
2. **天气**：部署机器需要放行 `geocoding-api.open-meteo.com` 与 `api.open-meteo.com`，并在设置里填常住城市；不放行也能用，只是退回按日期推断季节。
3. **合并**：P3、P4 两个分支都未合并到 main。P4 基于 P3，确认后可直接合并 P4（包含 P3 全部提交）。
