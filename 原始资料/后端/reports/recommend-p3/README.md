| 部分 | 内容 |
|---|---|

## 七、与设计的差异

| 设计 | 实际 | 原因 |
|---|---|---|
| 抠图或贴纸一律写实 | 抠图/整理图优先沿用同一次识图对原图的判断，没有识图结果才按来源记为写实 | 实库有 2 件贴纸是卡通图抠出来的，"抠图即写实"会判错 |
| 倾向"正面合计 − 负面合计再加先验平滑" | (正 − 负)/max(1, 正 + 负) | 用 +prior 的分母时"30 天后影响减半"不成立；max 形式一次不喜欢 −1、30 天后正好 −0.5 |
| 正面信号与负面对称计分 | 正面折算 0.3、合计最多 +6；组合层与单品层取最差和最好分开计 | 真实账号自测中保存过的搭配一律 100 分，且一次"不喜欢高跟鞋"被同套里常选的衬衫平均抵消 |
| 今天穿了这套"若未保存会提示先保存" | 推荐详情直接按衣物打卡 | 打卡只需要衣物集合，省一步；已保存搭配仍按 outfitId 记录 |
| 助手快捷入口结果插入聊天 | 只显示在当前聊天、不保存到对话记录 | 保持"零模型、不占次数"，不伪造一条助手消息进历史 |
| 换一件在列出替代品时记 SWAP_OUT | 采用时才上报 | 只看看不代表换掉 |
| 模板审核可选预览命中示例 | 未做 | 可选项；自测脚本里有"找出这个衣柜能命中的模板"的办法 |
| 画像"不准确"屏蔽 | 同时屏蔽对应的反馈层（整套/组合/同类/单品/混搭/偏移/闲置） | 屏蔽要真的不再影响推荐 |

## 八、需要你决定的事项（已按保守、可逆的方式实现）

1. **扣分幅度**：原排除格 −25、温度 −20/件、正式跨度 −20、不配鞋 −8（`feature-tables.json` 的 `penalties`）。如果仍希望某些组合（如运动场景穿高跟鞋）彻底不出现，可改回硬规则。
2. **反馈参数**：负面 30 天减半、冷却门槛（约两次不喜欢、预计 20 天左右恢复）、正面折算 0.3 与上限 +6（`feedback`）。
3. **高跟鞋的状态**：自测把它从旧暂停恢复后又点了两次"不喜欢"，现在冷却约 23 天；要彻底不推荐它，可在记忆里写"不穿高跟鞋"。
4. **模板库**：58 条仍全部待审核。实测这个衣柜能命中 gray-tonal、pattern-with-solid-top、monochrome-white，可以在 `/admin/templates` 审核。
5. **严格度默认档**：50（0.35/0.06）；如更想多给结果可默认 25（命中 100%，没有时 90% 如实说没有）。
6. **画风混搭默认**：自动学习，默认只 −3；你的衣柜只有 2 件卡通，影响很小。
7. **合并**：两个仓库的 `feat/outfit-recommend-p3` 已推送，确认后再合并到 main。8080 目前运行的是本分支（部署前数据备份在 `.local/backups/data-before-p3-20261008-235614`）。
