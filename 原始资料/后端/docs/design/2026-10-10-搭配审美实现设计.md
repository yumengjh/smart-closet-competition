## 二、整体流程（与 P4 的差异用 ★ 标出）

```
意图 + 衣柜 + 画像 + ★曝光（服务层从推荐日志算出）+ ★搭法语义（已缓存的描述向量）
  │
  ├─ 召回：硬排除（★冷却不清空主体位置）→ 相关度排序 → ★每位置 K 随 √n 增长、组合数上限 → ★约 30% 轮换名额
  ├─ 组合：上装×下装×鞋 + 连衣裙×鞋（同 P4）
  ├─ ★搭法路径：已审核搭法从全部可用衣物填位 → 补齐另一半与鞋 → 同一硬规则
  ├─ 评委：P4 七个维度（色彩改为“配色安全”，权重下调）+ ★审美组四个维度 + 规则加减
  │        ★外套计暖、★材质对避坑表、★季节感冲突、★曝光债/新入柜、★搭法风格放宽
  ├─ 多样化：主体重复让位（同 P4）+ ★近似并列按当日种子轮换 + ★结构/配色方案让位 + ★跨天限流
  └─ 卡片：亮点首条为★手法标题；★穿法建议进 tips；解释接口列出新规则
```

推荐时全部本地计算，零模型调用。唯一的模型使用是语义填位用到的本地 bge 文本向量；它只读取已缓存的向量，请求从不等待模型（第七节）。

### 4.2 面积与颜色

- 面积：连衣裙 0.65、背带 0.45、上装 0.35（外层在身上时 0.2）、内搭 0.1、下装 0.35、外层 0.45、鞋 0.08、配件不计。每件的色块按 `ratio` 分摊，全身归一化。
- 未测色衣物：颜色名映射代表色值（`colorNames` 46 个关键词按顺序匹配，"浅蓝"先于"蓝"），再退回色系代表值（`familyLab`）。**不打折**（设计 D85 修订了 19.5 的 0.8 折扣）。
- 中性色判定：chroma < 12；或大地色（色相 40°~100°、chroma < 32、L > 20）；或藏蓝（色相 240°~320°、L < 35）；或牛仔面料的蓝色块。

### 4.3 配色方案（`scheme.scores`）

| 方案 | 判定 | 基础分 |
|---|---|---|
| MONO 同色系深浅 | 有彩色只有一组（色相差 ≤ 30°），面积 > 35%，组内两件明度差 ≥ 20（或面积 ≥ 60% 且全身明度跨度 ≥ 20） | 0.9 |
| NEUTRAL_LAYERED 全中性有层次 | 有彩色面积 < 8%，全身明度跨度 ≥ 25 | 0.85 |
| PRINT_NEUTRAL 印花配中性 | 有未测色的多色衣物，其余为中性 | 0.85 |
| ACCENT 中性 + 一处点缀 | 一组有彩色，面积 8%~35% | 0.8 |
| STATEMENT 彩色单品 | 一组有彩色，面积 35%~60% | 0.75 |
| ANALOGOUS 邻近色 | 多组有彩色，两两色相差 ≤ 60° | 0.75 |
| CONTRAST_ACCENT 对比色点缀 | 两组，次要一组面积 ≤ 15% | 0.75 |
| MONO_FLAT 同色系无深浅 | 一组有彩色，面积 ≥ 60%，无明度差 | 0.7 |
| CLASH_ALLOWED 风格允许的撞色 | 同下，且风格词允许 `clash` | 0.7 |
| NEUTRAL 全中性 | 明度跨度 10~25 | 0.65 |
| UNKNOWN | 颜色资料不足 | 0.5 |
| NEUTRAL_FLAT 全中性无层次 | 明度跨度 < 10 | 0.5 |
| PRINT_COLOR / MIXED | 印花再配彩色 / 多组无章法 | 0.45 |
| CLASH 大面积撞色 | 两组各 ≥ 25%、chroma ≥ 35、色相差 ≥ 90° | 0.3 |

执行质量修正：呼应（同一有彩色组跨两件以上，+0.1）、灰调色与高饱和色各占 ≥ 10%（−0.15）、暖中性与冷灰白各占 ≥ 20%（−0.1）、上下明度差 ≥ 30（+0.05，全中性有层次不重复加）。

### 4.4 焦点、呼应与季节感、比例

- **焦点**：主角为视觉重量（面积 × min(1.5, chroma/40)）≥ 0.25 且 chroma ≥ 45 的有彩色块（同色相组合并为一个）、面积 ≥ 0.3 的强花纹或未测色印花、面积 ≥ 0.3 的蕾丝/丝缎/皮革/亮片；有印花时或有两件花纹时，花纹单品也算主角（花纹叠格纹）。一个主角 1.0、没有 0.7（极简 0.9）、两个以上 0.3（洛丽塔、哥特、地雷、量产 0.85）。
- **呼应与季节感**：基础 0.5；当季感 +0.5 ×（当季比例 − 0.5），即 ±0.25（12°C 以下标"冬"算当季、标"秋"算一半；24°C 以上标"夏"算当季、标"春"算一半；其间按意图季节、春秋互通）；鞋与主体色块 ΔE < 12 +0.2。季节冲突：两件季节标签都已知且无交集（春秋互通）且保暖值差 ≥ 2.5，或任一未知且涉及鞋、保暖值差 ≥ 2.8，此时该维度记 0.2，并触发规则 `season.mismatch` −8；鞋的季节与身上每件衣物都不重合但保暖差不大时为轻度 −3（如春秋衣物配夏季凉鞋）。上装×下装由冷暖维度原有规则负责；居家场景的拖鞋不参与。
- **比例**：版型由 `fit`（宽松/廓形、合体、修身）与品类、名称关键词推导（`silhouette`），长度由 `garmentLength` 与关键词推导。上松下紧或上紧下松 0.9；同松紧 0.7；上下都宽松 0.5，上衣为长款时 0.35（街头、工装、嘻哈、oversize、慵懒、宽松 0.7）；短上衣或塞进去的上衣配高腰下装或半身裙 +0.15；长上衣（不可塞）配长下装 −0.25。连衣裙有腰线 0.85、无腰线 0.65（衣柜里有腰带时提示系腰带）。**未知记 0.65**（已知情况的近似平均，见第九节差异）。

### 4.5 避坑表与风格列

| 表 | 格数 | 非 OK 的格 |

| 颜色对（14 个色系含自身） | 105 | 红绿、紫黄、橙紫、橙粉、红橙（PENALTY，与 P4 撞色对相同）；风格列：多巴胺、撞色、孟菲斯 → OK，街头、节日 → MILD |

- 风格词来源：用户想要的风格（原话与映射后的词）、全部主体衣物共有的风格标签、命中搭法的 `style`。多个风格词命中时取最宽松的结论。
- 颜色表只作用于"强调色"之间（同 P4 撞色规则的口径），材质表作用于主体与在身上的外层之间；两件都由用户指定时跳过。

| `shoeSwapGap` | 3 | 鞋已经在本页出现 n 次时，同一套换成本页还没出现的鞋，只要分数最多低 n × 3 分就换（第十三节） |
| `recipes.perSlot` | 3 | 每个位置最多取 3 件 |
| `recipes.floor` / `window` | 0.5 / 0.06 | 语义候选：相似度 ≥ 0.5 且与同位置第一名差 ≤ 0.06 |
| `recipes.high` / `faithfulGap` | 0.55 / 0.03 | 忠实：关键词命中，或 ≥ 0.55，或 ≥ 0.5 且领先同位置其他衣物 ≥ 0.03 |
| `recipes.maxFills` / `fillersPerRole` | 400 / 2 | 搭法候选上限、补齐另一半时每位置取前 2 件 |

## 五、评委改动细节（`OutfitScorer`）

1. **模板/搭法先算**：`templates.match` 移到最前；搭法路径传入的忠实搭法在关键词不命中时也算命中。命中搭法的 `style` 加入风格词。
2. **配色安全**（原色彩维度）：逻辑与 P4 相同，撞色改为查颜色对表，风格列 MILD 扣一半、OK 不扣并写"所选风格允许"。
3. **冷暖**：温度已知、主体保暖低于区间下限、有外套建议时，取让保暖值最接近区间的外套计入，依据写"加上建议的外层后保暖值 x"（不写外套名，避免理由核对把不在搭配里的品类判为不实），穿法建议写"天凉，出门加上{外套名}"。
4. **审美组**：`Aesthetics.assess` 返回四个维度、规则（季节冲突）、穿法建议、手法标题、方案名。审美组维度不写进提醒（缺少加分不是问题），也不参与新尝试的"每维 ≥ 0.6"检查。
5. **材质对**：替代 P4 的牛仔叠牛仔代码，规则 id 保持 `material.double-denim`（解释与考试题不变），其他材质格为 `material.pair`。
6. **曝光债**：放在闲置激活之后、仅在没有重扣分且闲置激活未触发时；新入柜与曝光债取较大者，不叠加。
7. **亮点顺序**：明确愿望 → 搭法名 → 手法标题（配色手法 ≥ 0.75 的正面依据，或比例 ≥ 0.85）→ 其余维度。有配色手法标题时，色彩维度的正面依据不再进亮点（快照页发现"黑白深浅分明"与"黑白经典"重复）。
8. **个人系数**（D75）：牛仔叠牛仔、材质对、季节冲突三类扣分乘以 `1 − 0.6 × 倾向`（接受，最低 0.4）或 `1 + 0.5 × |倾向|`（认同，最高 1.5），倾向 |x| < 0.05 不调整；依据追加"你接受过这样搭，扣分减小"或"你也觉得不好看，扣分加大"。倾向来源：点赞一套只被一条规则扣 ≥ 3 分的搭配记一次接受（权重 1）；不喜欢时每条扣 ≥ 3 分的规则记一次认同（权重 0.5）；衰减与屏蔽沿用 D28。

## 六、引擎改动细节（`RecommendationEngine`）

- **召回**：先算每个位置的 K（`recallSizes`），再排序、轮换、截断。轮换名额按曝光债降序、再按 `Balance.hash(种子, 衣物 id)`；被轮换选中的衣物在解释接口里写"轮换名额：相关度相近的衣物轮流出场"。
- **冷却上限**：主体位置（上装、下装、连衣裙、背带）至少 4 件且冷却超过一半时，按单品倾向放回最不讨厌的几件，限制里写明；鞋与小位置照用户反馈执行。
- **外套建议**：触发条件 = 冷（< 15°C 或冬季）或（温度已知、< 22°C、主体加鞋的保暖值低于个人化区间下限）；`OuterSuggestion` 带保暖值。
- **搭法路径**：见第七节。搭法候选与普通候选按 key 合并，同一套取分高者；被搭法用到而召回时截断的衣物，在追踪里改为"通过搭法进入候选"。
- **多样化**：`adjusted = (总分 + 1.5 × hash(种子, 搭配 key)) × 主体重复系数 × 结构系数 × 方案系数 × 限流系数`。新尝试位逻辑不变。
- **换一批**：沿用这次推荐的曝光与种子；首轮放回的冷却衣物记在 `stats.releasedCooldowns`，换一批时同样可用。
- **换一件**：曝光为空（不影响替代品打分），外套计暖与审美组照常。

## 七、搭法路径与语义填位

1. **适用搭法**：已审核且启用、人群/季节/有效期适用，场合不限或包含当前场合（日常意图不过滤场合），与今日灵感一致。
2. **每个位置的候选**：通过关键词约束（`accepts`）的衣物，排序分 1 + 相关度；有 `describe` 且服务层提供了相似度时，再加同位置、同色系约束下相似度 ≥ 0.5 且与第一名差 ≤ 0.06 的衣物，排序分加相似度。取前 3 件。任一位置没有候选则跳过该搭法（"差一件"提示仍由今日灵感负责）。
3. **组合**：各位置候选的笛卡尔积（同一件不重复），用户指定的同位置衣物优先；缺的上装/下装与鞋从召回结果里各取前 2 件补齐。总数不超过 400。
4. **忠实**：所有位置都"关键词命中或语义忠实"才把搭法传给评委（显示"经典搭法：…"并加分）；否则按自由组合打分。
5. **语义向量**（服务层）：`slotSemantics` 收集已审核搭法的全部 `describe`，只读取已缓存的描述向量；有缺的就调用 `warmDescribes` 在后台虚拟线程里逐条编码（独立缓存，上限 4096，换模型自动清空），本次请求按关键词填位，下次请求起生效。搭法全是草稿时什么也不做。
6. **标定**（`RecipeSlotEvaluationTest`，本地 bge-small-zh fp32）：41 件标注衣柜，24 个正例描述同位置第一名全部正确，相似度 0.519~0.707；10 个衣柜里没有的反例，同位置最高相似度 0.385~0.544。只用绝对门槛分不开（0.58 时正例只剩 16/24；0.51 时"黄色T恤"会以 0.544 误配白T），加上"领先同位置其他衣物 ≥ 0.03"后正例 24/24 忠实、反例 0/10。原始数据：`reports/recommend-aesthetic/recipe-slot-eval.json`。

## 八、服务层（`RecommendationService`）

- **曝光**：`SELECT garment_ids_json, created_at_ms FROM recommendation_log WHERE owner=? AND created_at_ms >= 30 天前 AND rank_no <= 3`（首页，任何来源）；每件衣物取最近出现日期，14 天内统计包含它的首页套数占比（至少 6 套才计算）；`SELECT id, created_at_ms FROM garment WHERE owner=? AND closet_status='ACTIVE'` 得到入柜天数。从未出现的衣物，曝光债 = min(30, 入柜天数)。
- **种子**：`用户|日期（上海时区）|场景|温度取整|季节|想要的风格|颜色|品类|自由描述|指定衣物`。同一天同一意图结果稳定，"换一批"沿用同一次结果。
- **开关**（`application.yml`）：`closet.recommend.aesthetic-enabled`、`balance-enabled`、`outer-warmth-enabled`、`recipes-enabled`，环境变量 `CLOSET_RECOMMEND_AESTHETIC`、`CLOSET_RECOMMEND_BALANCE`、`CLOSET_RECOMMEND_OUTER_WARMTH`、`CLOSET_RECOMMEND_RECIPES`，默认全开。关闭后重启即回到 P4 对应行为，无数据迁移。
- **影子运行**：`closet.recommend.shadow-enabled`（`CLOSET_RECOMMEND_SHADOW`，默认关）。每次页面推荐在虚拟线程里用 `Mechanisms.LEGACY` 再算一遍，写一行日志 `recommend shadow owner=… served=… shadow=… sameOutfits=x/n sharedGarments=… servedTop=… shadowTop=… servedPool=… shadowPool=… shadowMs=…`，只含衣物 id，不展示、不入库。
- **规则命中日志**：`recommendation_log.rule_hits_json` 记录 `{规则 id: 扣分}`（只记牛仔叠牛仔、材质对、季节冲突），供个人系数与以后的健康度统计。
- **版本**：`recommendation_log.rule_version` 记 `outfit-score-v4/` 加开启的机制字母（a 审美组、b 均衡、o 外套计暖、r 搭法），统计可按版本拆分；`stats` 里有 `aestheticRulesVersion`、`mechanisms`、`recipeCandidates`。

## 十三、真实衣柜反馈修正（2026-10-10）

用户用真实衣柜测试时发现三个问题：

1. **玛丽珍鞋配灰背带裤加 T 恤得 95 分**，依据写“主体都偏休闲风”。原因：风格维度只看主体，鞋不参与。
2. **鞋子总挑同一双**。原因：多样化只比较主体衣物；某双鞋个人偏好高一点，就在每个主体上都胜出，整页都用它。
3. **配色依据写“黑色和粉色与粉色是邻近色”**。原因：色块按所属衣物的主色命名，黑色背带裙上的粉色色块被叫成“黑色”；两组都叫粉色时也照写“邻近色”。

修正如下，鞋的风格和色块命名受 `closet.recommend.aesthetic-enabled` 控制，鞋子轮换受 `closet.recommend.balance-enabled` 控制，开关关掉时回到 P4 行为：

- **鞋的风格**（`aesthetic-rules.json` 的 `shoeStyle`）：
  - 先按名称和品类认出鞋款，取鞋款的风格，再并上鞋自己的风格标签。例如玛丽珍鞋是甜美、复古、通勤；乐福鞋、牛津鞋是通勤、复古、正式；运动鞋是运动、休闲、户外。
  - 与主体所有风格都不重合时，风格维度扣 0.3（约 3.6 分），依据写“玛丽珍鞋偏甜美/复古/通勤，和休闲风的主体不太搭”。
  - 靴子、凉鞋算百搭，认不出的鞋款不判断。只看识图写的风格标签太窄，例如棕色“复古”短靴配藏蓝毛衣本来就好看，考试题也守着这一点。
- **鞋子轮换**（`RecommendationEngine.otherShoe`）：选出一套后，如果它的鞋已经在本页出现 n 次，就改用同一套主体配本页还没出现的鞋，前提是分数最多低 n × `shoeSwapGap`。只换鞋，不换主体，所以搭配排序不变。
- **色块命名**：每个色块按自己最接近的彩色色族命名。接近衣物主色或中性色时，仍用衣物自己的颜色名。两组名字相同时，写“粉色色调略有不同，过渡自然”。

守护测试是 `ShoeFeedbackTest`（3 题），每题都在去掉修正后会失败；同时 GoldenOutfitsTest、AestheticSpreadTest、ExposureBalanceTest、StyleLooksTest 全部通过。快照页已重新生成。

**用户确认后的第二轮修正**：

- **围裙式背带裙/背带裤单穿**：用户说“穿了围裙式背带裙，上身基本上就完了，可能还有丝袜搭配，但衬衫是不应该的”。
  - 名称或品类含“围裙”且原本是 `OVERALL` 的衣物，按 `ONE_PIECE` 单穿，不配上衣。
  - 实现是 `OutfitRules.markWornAlone`，推荐、助手候选和搭配检查都调用它。
  - 天凉时照常建议裤袜。
  - 普通背带裤配 T 恤不变。
- **主体风格完全不重合扣得更多**：用户授权由我决定。
  - `aesthetic-rules.json` 的 `styleMix.floor`：风格维度起点从 0.5 改为 0.3，风格权重 12 时多扣约 2.4 分。
  - 用户说了风格画像词（多巴胺、甜一点）时仍为 0.5，此时由画像线索判断风格，否则黄色背带裙配白衬衫这类多巴胺搭配会被粗标签误伤（StyleLooksTest 守护）。
  - 开关关掉时为 0.5。

## 十四、全项目审核修正（2026-10-11）

外部模型（gpt-6-sol）审核引擎代码后，经人工逐条核实，修正以下问题。每项都有修复前失败的测试。完整对照见 [2026-10-11 优化记录](../../reports/optimization-2026-10-11/README.md)。

- **开关全关回到 P4**：
  - 撞色格和材质避坑表原本不受开关控制。
  - 现在 `aesthetic` 关闭时走 P4 的固定撞色表 `clashPairs`，以及只看主体的牛仔叠牛仔规则（`MechanismParityTest`）。
- **鞋款风格**：
  - 第十三节「并上鞋自己的风格标签」有漏洞：识别几乎给每双鞋都标「休闲」，玛丽珍鞋于是总能和休闲主体「重合」。
  - 现在 `shoeStyle.weakTags`（休闲、日常、百搭）不再并入，具体标签照常并入。
- **换单品**：替代品遵守召回阶段的全部硬排除（本次排除、避色、避品类、品类存疑、名称错类），不再只看冷却。
- **建议外套**：
  - 审美开启时，外套风格与主体重合加 `balance.outerStyleBonus`（0.1），完全不重合减 `outerStylePenalty`（0.25）。
  - 因为外套的保暖值会计入整套得分，它必须和这套搭得上。
- **翻页**：`more()` 重算时沿用首屏的搭法和衣柜品类（`stats.closetRoles`），语义填位的搭法不再在翻页后丢掉加分和名称。
- **裤袜提醒**：本次没有建议裤袜、而天凉露腿时一律提醒；只有衣柜确实没有裤袜时才说「还没有」。
- **冷却救回**：「超过一半在冷却」只按本次可用的衣物计数。
- **未知颜色**：
  - 颜色未知的衣物在色板里保留面积，不再让鞋的颜色被放大成整套。
  - 未知面积超过 `scheme.maxUnknownArea`（0.4）时，配色手法不评。
