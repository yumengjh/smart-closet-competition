推荐引擎流水线

1结构化意图

场景、温度、季节、风格词、颜色、必选/排除衣物。页面直接给参数；聊天时由模型填写意图，计算仍在后端。

2衣物特征

属性 + 证据状态 + 实测 CIELAB 色板 + 风格画像吻合度。推测不升级为事实。

3按位置召回

上装/下装/一体/鞋/外套分桶；动态 K：K(n)=max(K₀, min(2K₀, ⌈1.5√n⌉))，库存越大召回越宽。

4两路候选

① 普通组合（预算 2400）；② 已审核搭法语义填位（74 条资源，忠实度 ≥0.55 才算该搭法）。

8结果与追踪

卡片附亮点、依据、规则命中；记录日志支持“为什么没推荐那件”、换一批、换一件。

7多样化重排

共用主体 ×0.7 / ×0.3；曝光债与跨天限流；稳定种子 hash(用户,日期,意图)，不随机洗牌。

611 维评分

总分 = clip(Σ 维度分×场景权重 + Σ 规则加减分, 0, 100)；色彩、冷暖、风格、场景、配色手法、比例…

5底线检查

只留硬底线：穿着结构、用户明确表达、男性×女款。其余一律软扣分并写依据。

零模型调用：召回、组合、打分、换一批、换一件、今日灵感、搜索、取色都在 Java 内计算（检索可用本地 ONNX 向量）。
模型只做两件事：聊天时理解自然语言并填意图；拿到压缩后的结果卡向用户解释。不向模型发送完整衣物资料、性别或身材数据。
